## Panoramica

Il backend mock tiene tutti i dati in memoria. È il backend predefinito e non richiede servizi esterni.

## Cosa Fa

- Carica le categorie predefinite da `@/lib/categories` e nient'altro: si parte senza conti e senza transazioni.
- Accetta qualsiasi email e password all'accesso. La password non viene controllata.
- Implementa gli stessi metodi di `DatabaseAdapter` del backend Firebase, quindi i test contrattuali girano su entrambi.
- Dimentica tutto al ricaricamento della pagina.

## Utilizzo

```ini
NEXT_PUBLIC_BACKEND=mock
```

Poi esegui `pnpm dev`.

## Nei Test

I test Vitest usano il backend mock. Azzera il suo stato prima di ogni test:

```typescript
import { createMockAdapter, __resetMockState } from "../mock"

beforeEach(() => {
  __resetMockState()
  adapter = createMockAdapter()
})
```

I test end-to-end girano su una build di produzione con il backend mock. Per vedere uno stato di caricamento, che il mock altrimenti risolve subito, imposta `window.__MOCK_LATENCY_MS__`; vedi [Test](/docs/contributing/testing).
