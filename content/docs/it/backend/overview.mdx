## Pattern Adapter

Tutto ciò che l'app legge o scrive passa dall'adapter. Il codice delle funzionalità non importa mai Firebase direttamente.

```typescript
import { getBackend } from "@/lib/backend"

const backend = getBackend()
const accounts = await backend.db.getAccounts(userId)
```

## Interfaccia

```typescript
interface BackendAdapter {
  auth: AuthAdapter
  db: DatabaseAdapter
  ai: AIAdapter
}
```

`AIAdapter` non ha alcun provider dietro; vedi [Architettura](/docs/architecture).

### DatabaseAdapter

`DatabaseAdapter` copre:

- **Conti**, **transazioni** (con filtri e importazioni), **categorie**, **budget**, **obiettivi di risparmio**
- **Transazioni ricorrenti**, incluso `generateDue`
- **Tag** e **regole di categorizzazione**, incluso `applyCategorization`
- **Patrimonio netto**: snapshot e storico
- Aggregati per **dashboard** e **report**
- **Chiavi API** e suggerimenti di abbonamento scartati

Il registro di audit MCP non è su `DatabaseAdapter` di proposito: la sua collezione è chiusa ai client dalle regole, quindi si raggiunge sul server tramite `getServerDb()`.

## Selezionare un Backend

Imposta `NEXT_PUBLIC_BACKEND` in `apps/web/.env.local`:

| Valore | Backend | Uso |
|---|---|---|
| `mock` | Archivio in memoria | Sviluppo, test |
| `firebase` | Firestore e Firebase Auth | Self-hosting, distribuzione |
