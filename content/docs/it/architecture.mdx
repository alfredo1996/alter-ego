## Workspace

Il repository è un workspace pnpm.

```
apps/web/                 # l'app Next.js (@alter-ego/web)
├── src/
│   ├── app/
│   │   ├── (auth)/       # /login, /register
│   │   ├── (app)/        # dashboard, conti, transazioni, categorie,
│   │   │                 #   budget, obiettivi, ricorrenti, report, impostazioni
│   │   ├── api/          # API REST (v1), server MCP, OAuth, chiavi API
│   │   └── [lang]/docs/  # questa documentazione
│   ├── components/       # componenti delle funzionalità
│   ├── hooks/            # hook TanStack Query
│   ├── lib/
│   │   ├── backend/      # l'adapter: types, mock, firebase, firebase-admin
│   │   ├── mcp/          # strumenti MCP
│   │   ├── oauth/        # server OAuth 2.1 per l'endpoint MCP
│   │   └── ...           # categorie, ammortamento, import CSV, patrimonio netto, ...
│   ├── stores/           # store Zustand
│   └── types/            # tipi condivisi e schemi Zod
packages/
├── kernel/               # @alter-ego/kernel: helper per valuta e date
└── ui/                   # @alter-ego/ui: primitive shadcn/ui, il page kit, cn()
firestore/                # i sorgenti di firestore.rules
```

Il kernel non importa nulla dall'app, e il kit UI importa solo il kernel e le proprie dipendenze. Un test di confine in ogni pacchetto fallisce su un import vietato.

## Pattern Adapter Backend

Ogni accesso ai dati passa da un unico adapter. Il codice delle funzionalità non importa mai Firebase direttamente.

```typescript
import { getBackend } from "@/lib/backend"

const backend = getBackend()
await backend.db.getAccounts(userId)
```

`NEXT_PUBLIC_BACKEND` seleziona `mock` o `firebase`. Vedi la [Panoramica Backend](/docs/backend/overview).

## Server MCP e API REST

Gli stessi dati sono disponibili fuori dal browser:

- **Server MCP** su `/api/mcp`, via HTTP con OAuth 2.1 e PKCE (il server di autorizzazione è in `lib/oauth`), oppure via stdio con `pnpm mcp:stdio`. Gli strumenti sono in `lib/mcp/tools`.
- **API REST** sotto `/api/v1`, autenticata con una chiave API dalle Impostazioni. Il suo documento OpenAPI è servito su `/api/openapi`.

Entrambi raggiungono il database tramite l'adapter lato server, non con l'SDK del browser. [docs/SELF-HOSTING.md](https://github.com/alfredo1996/alter-ego/blob/main/docs/SELF-HOSTING.md) elenca gli strumenti.

## Gestione dello Stato

- **Stato server**: TanStack Query, con hook come `useAccounts` e `useTransactions`.
- **Stato client**: Zustand (`useSettingsStore`) per impostazioni come valuta, locale, tema e `aiMode`.
- **Form**: React Hook Form con schemi Zod.

## AI

L'app non ha bisogno dell'AI e nessuna è collegata. `AIAdapter` è un punto di innesto con due metodi: `chat()` restituisce una frase fissa e `categorize()` restituisce `null` in entrambi gli adapter. Il flag `aiChat` è `false`, quindi la voce della chat non viene mostrata. Le Impostazioni hanno un selettore `aiMode` (Off, Local, Cloud) che viene salvato ma per ora non cambia nulla.

## Stile

- Tailwind CSS v4, con `cn()` per le classi condizionali.
- Primitive shadcn/ui in `packages/ui`; mantieni le loro API e aggiungi una variante invece di rinominarne una.
- I grafici sono SVG puri, senza libreria di grafici.
