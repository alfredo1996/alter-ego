## Unit Tests (Vitest)

**354+ unit tests** cover utilities, business logic, and the mock backend adapter.

```bash
# Watch mode
pnpm test

# Single run
pnpm test --run

# With coverage
pnpm test --run --coverage
```

### Test Files

Tests live in `__tests__/` directories next to the code they test:

```
src/lib/__tests__/
  ├── dates.test.ts
  ├── export.test.ts
  ├── merchants.test.ts
  ├── net-worth.test.ts
  ├── amortization.test.ts
  └── ...
src/lib/backend/__tests__/
  ├── adapter-contract.ts  # Shared contract tests
  ├── mock.test.ts
  ├── mock.adapter.test.ts
  └── firebase.adapter.test.ts
```

### Mock Backend in Tests

Always reset state between tests:

```typescript
import { getBackend } from "@/lib/backend"

beforeEach(() => {
  const backend = getBackend()
  ;(backend as any).__resetMockState()
})
```

### Contract Tests

The adapter contract test suite (`adapter-contract.ts`) defines 97 shared tests that any backend adapter must pass. They run against the mock adapter on every `pnpm test`, and against Firebase under the emulator with `pnpm test:firebase:docker`.

## E2E Tests (Playwright)

E2E tests cover critical user flows using the mock backend. **18 spec files** across all major features.

```bash
pnpm test:e2e
```

### Test Specs

```
e2e/
  ├── auth.spec.ts              # Login, register
  ├── dashboard.spec.ts         # Dashboard widgets, drill-down
  ├── accounts.spec.ts          # Account CRUD
  ├── account-detail.spec.ts    # Account detail, balance chart
  ├── transactions.spec.ts      # Transaction CRUD, filters
  ├── categories.spec.ts        # Category management
  ├── budgets.spec.ts           # Budget CRUD, alerts
  ├── savings-goals.spec.ts     # Goal CRUD, add funds
  ├── recurring.spec.ts         # Recurring rule CRUD
  ├── reports.spec.ts           # Charts, period selector
  ├── mm-import.spec.ts         # Money Manager import flow
  ├── navigation.spec.ts        # Sidebar, mobile nav
  ├── settings.spec.ts          # Settings sections
  ├── sign-out.spec.ts          # Sign-out flow, protected routes
  ├── mobile.spec.ts            # Phone layout: nav sheet, dialogs, selects

  ├── oauth-consent.spec.ts     # OAuth consent screen
  └── security-headers.spec.ts  # CSP and security headers
```

### Patterns

- Tests run against the mock backend for speed and isolation
- Use `aria-label` and role-based selectors for accessibility
- Desktop-only interactions (hover menus, dropdowns) are tested in desktop viewport
