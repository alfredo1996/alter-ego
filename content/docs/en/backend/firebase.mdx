## Overview

The Firebase backend stores data in Firestore and signs users in with Firebase Authentication. Sign-up is closed: the security rules admit one user id.

## Data Model

Each user's data lives in subcollections of `users/{userId}`:

```
/categories                          default categories (read-only for clients)
/users/{userId}/
  ├── accounts/
  ├── transactions/
  ├── categories/                    the user's own categories and copies of defaults
  ├── budgets/
  ├── savings_goals/
  ├── recurring/
  ├── tags/
  ├── categorization_rules/
  ├── dismissed_subscription_patterns/
  ├── account_balance_snapshots/
  ├── monthly_totals/
  ├── net_worth_snapshots/
  ├── api_keys/
  └── mcp_audit/                     server-only
/api_keys_index                      key hashes, for server-side validation
/oauth_clients, /oauth_codes, /oauth_tokens    OAuth server, server-only
```

The server-only collections are written through the Admin SDK, which bypasses the rules; the rules deny every client access to them.

## Configuration

```ini
NEXT_PUBLIC_BACKEND=firebase
NEXT_PUBLIC_FIREBASE_API_KEY=your-api-key
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=your-project.firebaseapp.com
NEXT_PUBLIC_FIREBASE_PROJECT_ID=your-project
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=123456
NEXT_PUBLIC_FIREBASE_APP_ID=1:123456:web:abcdef
```

The REST API and the MCP server also need server credentials: set `FIREBASE_SERVICE_ACCOUNT_JSON` (the service account as JSON) or `GOOGLE_APPLICATION_CREDENTIALS` (the path to its key file).

## Security Rules

`firestore.rules` is generated from `firestore/base.rules` by `pnpm rules:build`. Edit the source, not the output; a test fails when they differ. The rules:

- admit one user id (`isAllowedUser`) and let that user reach only their own subtree;
- give every collection a closed schema: a write may carry only the fields the app writes, and each field is validated (types, bounds, allowed values);
- make the default categories and the OAuth and audit collections unreachable for writes from a client.

## Key Implementation Details

- **Categories** merge the root defaults with the user's own.
- **Net worth snapshots** use the date as the document id, so there is one snapshot per day and a later one the same day replaces it.
