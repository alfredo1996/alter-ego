## Overview

The mock backend keeps all data in memory. It is the default backend and needs no external service.

## What It Does

- Seeds the default categories from `@/lib/categories` and nothing else: you start with no accounts and no transactions.
- Accepts any email and password at sign-in. The password is not checked.
- Implements the same `DatabaseAdapter` methods as the Firebase backend, so the contract tests run against both.
- Forgets everything when the page reloads.

## Usage

```ini
NEXT_PUBLIC_BACKEND=mock
```

Then run `pnpm dev`.

## In Tests

Vitest tests use the mock backend. Reset its state before each test:

```typescript
import { createMockAdapter, __resetMockState } from "../mock"

beforeEach(() => {
  __resetMockState()
  adapter = createMockAdapter()
})
```

End-to-end tests run against a production build with the mock backend. To see a loading state, which the mock otherwise answers at once, set `window.__MOCK_LATENCY_MS__`; see [Testing](/docs/contributing/testing).
