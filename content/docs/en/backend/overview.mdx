## Adapter Pattern

Everything the app reads or writes goes through the adapter. Feature code never imports Firebase directly.

```typescript
import { getBackend } from "@/lib/backend"

const backend = getBackend()
const accounts = await backend.db.getAccounts(userId)
```

## Interface

```typescript
interface BackendAdapter {
  auth: AuthAdapter
  db: DatabaseAdapter
  ai: AIAdapter
}
```

`AIAdapter` has no provider behind it; see [Architecture](/en/docs/architecture).

### DatabaseAdapter

`DatabaseAdapter` covers:

- **Accounts**, **transactions** (with filters and imports), **categories**, **budgets**, **savings goals**
- **Recurring transactions**, including `generateDue`
- **Tags** and **categorization rules**, including `applyCategorization`
- **Net worth** snapshots and history
- **Dashboard** and **reports** aggregates
- **API keys** and dismissed subscription suggestions

The MCP audit trail is deliberately not on `DatabaseAdapter`: its collection is closed to clients by the rules, so it is reached on the server through `getServerDb()`.

## Selecting a Backend

Set `NEXT_PUBLIC_BACKEND` in `apps/web/.env.local`:

| Value | Backend | Use |
|---|---|---|
| `mock` | In-memory store | Development, tests |
| `firebase` | Firestore and Firebase Auth | Self-hosting, deployment |
